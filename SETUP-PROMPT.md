# Промт для Codex — настройка Codex Workspace Launcher с нуля

> Скопируй текст ниже (всё, что в кавычках) и вставь его в Codex.
> Codex сам всё установит и настроит. Работает на macOS, Linux и Windows.

```
Ты — системный инженер. Настрой мне "Codex Workspace Launcher" на этой машине.

ЦЕЛЬ: чтобы я мог выбрать проект и открыть в нём нужный AI-инструмент
(Codex, Claude, Muse, Qwen и т.д.) с нужным режимом запуска. Это программа
на Python из этого репозитория: пикер (красивая локальная страница в
браузере) + команды терминала.

ВАЖНО:
- У меня свои подписки/логины для инструментов. Их не запрашивай и не сохраняй.
- Никаких секретов, токенов, ключей и паролей не записывай в файлы проекта
  и не выводи в отчёт. Это публичный репозиторий.
- Определи ОС сам (macOS / Linux / Windows) и используй её штатные способы.

ШАГИ (по порядку):

1. Определи ОС. Проверь Python 3.8+ (python3 --version).
   Если нет — установи штатным способом
   (macOS: brew install python; Linux: apt/dnf; Windows: python.org).

2. Установи команду "codex-workspace":
   - macOS:   bash install/macos-install.sh
   - Linux:   bash install/linux-install.sh
   - Windows: install\windows-install.bat
   Убедись, что команда работает: `codex-workspace --version` или
   `python3 launcher.py --version`.

3. Настрой список проектов. Спроси меня, какие папки — мои проекты, и
   добавь их: `codex-workspace add <путь> --label "Имя"`.
   Если проектов много — предложи задать переменную CODEX_WORKSPACE_ROOTS
   (родительская папка или список папок через двоеточие / точку с запятой).

4. Проверь инструменты: `codex-workspace tools` (список с версиями и
   статусами) и `codex-workspace doctor` (здоровье проектов).
   Инструменты, которых нет, не устанавливай сам — просто перечисли их мне
   в отчёте с указанием, как их поставить.

5. Сделай безопасную проверку БЕЗ открытия окон и запуска инструментов:
   `codex-workspace list --json`, `codex-workspace tools --json`,
   `codex-workspace open <id> --tool codex --mode safe --dry-run`.
   Все три должны отработать без ошибок.

6. Проверь пикер без открытия браузера у меня на глазах не нужно —
   просто убедись, что файл cwl/picker.html читается и сервер пикера
   отвечает на /api/health (это можно проверить скриптом, не запуская pick).

7. В конце дай короткий отчёт (по-русски, простыми словами):
   - что установлено и работает;
   - как я открываю пикер (команда или ярлык);
   - как добавить новый проект;
   - какие инструменты найдены, а каких нет и почему.

ПРАВИЛА КАЧЕСТВА:
- Не меняй и не удаляй существующие файлы проекта без причины.
- Действуй минимально и безопасно, без лишних файлов.
- Ничего не публикуй и не отправляй наружу без моей команды.
- Считай задачу готовой только когда шаги 2, 4 и 5 реально прошли.
```
