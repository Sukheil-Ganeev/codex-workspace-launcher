# R003 — последовательные повреждения реестра сохраняют все копии

## Проблема

После первого повреждённого `registry.json` файл сохраняется как
`registry.json.corrupt`. Если новый файл тоже повреждён, следующий запуск
`Registry` вызывает `os.replace` в тот же путь и молча перезаписывает первую
резервную копию. Старые данные теряются именно при попытке их сохранить.

## Ожидаемое поведение

- Существующая `registry.json.corrupt` не меняется.
- Следующие повреждённые файлы сохраняются в свободные имена рядом, начиная с
  `registry.json.corrupt.1`.
- Реестр по-прежнему запускается с пустыми данными и предупреждает о сохранённом
  файле.

## Сделано

При занятости основного `.corrupt`-пути реестр выбирает первое свободное имя с
числовым суффиксом (`.corrupt.1`, `.corrupt.2`, ...), не меняя прежние копии.
Добавлена проверка последовательной обработки двух разных повреждённых файлов.
